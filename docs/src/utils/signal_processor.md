# Documentation for `src/utils/signal_processor.py`

This file contains the `SignalProcessor` class, which acts as the central hub for receiving, validating, and executing trade signals generated by the various strategies.

## Core Responsibilities

1.  **Signal Reception and Filtering**:
    -   Its main entry point is the `process_signals` method, which takes a list of signal dictionaries from the `TradingBot`.
    -   It performs initial filtering on these signals, discarding any that have low confidence scores or are duplicates of recently processed signals.

2.  **Pre-Execution Validation**:
    -   Before executing any trade, it performs a critical real-time validation check using `_validate_signal_with_real_time_data`.
    -   This method fetches the latest tick data from the `MT5Handler` and compares the current market price to the entry price in the signal. If the prices have diverged by more than a configured tolerance, the signal is rejected. This prevents entering trades at a bad price due to market slippage or stale data.

3.  **Risk Management Integration**:
    -   After passing the real-time check, the signal is sent to the `RiskManager` for a final, comprehensive validation.
    -   The `RiskManager` checks the trade against all its rules (max risk per trade, concurrent positions, etc.) and, crucially, returns the **final, calculated position size**.

4.  **Trade Execution**:
    -   If the `RiskManager` approves the trade, the `SignalProcessor` calls the `execute_trade_from_signal` method.
    -   This method uses the `MT5Handler` to place the market order with the correct symbol, direction, volume (provided by the `RiskManager`), stop-loss, and take-profit levels.

5.  **Position Management Integration**:
    -   It handles signals in the context of existing open positions for a symbol.
    -   Based on the `allow_position_additions` configuration, it can either add to an existing position or reject the new signal.
    -   If a signal involves multiple take-profit levels, it registers the newly opened trade with the `PositionManager` so that it can be managed for partial closes.

6.  **Notifications**:
    -   After a trade is successfully executed (or if it fails), it uses the `TelegramBot` instance to send a detailed notification to the user, summarizing the trade's parameters and the reasoning behind it.

## Key Features and Methods

-   **`async def process_signals(self, signals)`**: The main loop that orchestrates the entire process from signal reception to execution.

-   **`_is_signal_recently_processed(self, signal)`**: A de-duplication mechanism that uses a hash of the signal's key parameters to check if an identical signal has been processed within a configurable time window.

-   **`async def _validate_signal_with_real_time_data(self, signal)`**: A crucial safety check to ensure the market hasn't moved significantly since the signal was generated.

-   **`async def execute_trade_from_signal(self, signal)`**: The final step that interacts with the `MT5Handler` to place the trade on the market.

-   **`async def handle_signal_with_existing_positions(self, signal, existing_positions)`**: Contains the logic for deciding what to do when a new signal arrives for a symbol that already has one or more open trades.

## How It's Used

-   The `SignalProcessor` is instantiated by the `TradingBot`.
-   Its `process_signals` method is called by the `TradingBot`'s main loop whenever any of the active strategies generate one or more signals. It acts as the final step in the chain from market data analysis to trade execution.
